# AIDocument

기획과 시스템 문서를 모으는 곳. 사람(기획자)과 AI 가 같이 읽는다.

최종 수정: 2026-11-16

---

## 폴더 구조

| 위치 | 무엇 | 언제 쓰나 |
|---|---|---|
| `진행_현황.md` | 지금 단계, 다음 할 일, 보류 중인 일 | **새 세션 시작 시 가장 먼저 읽는다.** 작업이 끝날 때마다 갱신 |
| `결정_기록.md` | 중요한 결정과 이유 | 결정을 내리거나 뒤집을 때 맨 아래에 추가 |
| `기획/` | 게임 전체 기획서와 기능별 기획서 | 기획 대화가 끝나고 합의한 내용을 적을 때 |
| `설계/` | 기술 설계 (아키텍처 등). "어떻게 만드나" | 코드 구조를 정하거나 바꿀 때 |
| `플레이테스트/YYYY-MM-DD_<내용>.md` | 플레이해 보고 느낀 점, 재밌었던 것과 아니었던 것 | 시제품이나 새 기능을 플레이해 본 뒤. 기존 파일을 고치지 않고 새 날짜로 새 파일 |
| `시스템/<시스템명>/SYSTEM.md` | 시스템별 현재 상태 문서 (무기, 적, 성장, 웨이브 등) | 그 시스템을 처음 구현할 때 만들고, 바뀔 때마다 갱신 |
| `WORK_TEMPLATES/` | 작업 기록 양식 (기능 개발, 버그 수정) | 작업 시작 시 복사해서 쓴다 |
| `_TEMPLATE_PLAN.md` | 기획서 양식 | `/design` 으로 기획서를 쓸 때 복사 |
| `_TEMPLATE_SYSTEM.md` | 시스템 문서 양식 | 새 시스템 문서를 만들 때 복사 |

## 문서 종류의 차이

- **기획서** (`기획/`): "무엇을, 왜" 만드는가. 구현 전에 쓴다. 기획이 바뀌면 고친다
- **시스템 문서** (`시스템/`): "지금 어떻게 만들어져 있는가". 구현 후에 쓴다. 코드와 항상 맞아야 한다

## 파일 이름 규칙

- 기획서: `기획/YYYY-MM-DD_<주제>.md` (예: `기획/2026-11-16_게임_전체_기획.md`)
- 시스템 문서: `시스템/<시스템명>/SYSTEM.md` (예: `시스템/무기/SYSTEM.md`)

## 새 시스템 문서를 만들 때

1. `_TEMPLATE_SYSTEM.md` 복사
2. `시스템/<시스템명>/SYSTEM.md` 로 저장
3. 내용 채우기
4. 아래 목록 표에 행 추가
