# /design - 기획 (코드 없이 무엇을, 왜 만들지 정한다)

게임이나 기능의 기획을 사용자와 토론해서 정하고, 합의한 내용을 기획서로 남긴다.
**코드, 씬, 에셋은 만들지 않는다.** 개발은 기획서가 승인된 뒤 별도로 한다.

기획 대상: $ARGUMENTS
(비어 있으면 대화 맥락에서 찾고, 그래도 없으면 무엇을 기획할지 묻는다)

---

## 1. 시작 전에 읽기

- `AIDocument/README.md` 의 문서 목록
- 기획 대상과 관련된 기존 기획서 (`AIDocument/기획/`) 와 시스템 문서 (`AIDocument/시스템/`)
- 이미 정해진 것과 충돌하는 제안을 하지 않기 위해서다. 충돌이 보이면 먼저 짚는다

## 2. 토론 방식

- **한 번에 질문 하나.** 메시지 끝에 질문 하나만 둔다
- **열린 질문 먼저.** "어떤 순간이 재밌었나", "이 기능을 쓰는 장면을 설명해 달라" 처럼 사용자가 자기 말로 그리게 한다.
  선택지는 사용자가 막혔을 때만 짧게 준다
- 사용자가 "알아서 해", "너는 어때" 라고 하면 구체안을 하나 제안한다. 여러 개를 나열하지 않는다
- **예외를 먼저 짚는다.** 모호한 것만 묻지 말고, 아래 점검 축에서 빈틈을 찾아 기획자처럼 먼저 제기한다
- **중간 정리.** 한 부분을 이해했으면 짧게 (200~300자) 되돌려 말하고 틀린 것이나 빠진 것을 묻는다.
  사용자가 말한 것과 AI 가 짐작한 것을 나눠 표시한다
- Unity 나 게임 개발 용어는 풀어서 말한다. 사용자는 기획자이고 Unity 는 처음이다

## 3. 게임 기획 점검 축

해당하는 축마다 질문이나 제안을 만든다. 순서대로 읽어주지 않는다.

| 축 | 짚을 것 |
|---|---|
| 재미 핵심 | 이게 왜 재밌나. 플레이어가 "한 판 더" 를 누르는 이유 |
| 경험 흐름 | 처음 10초, 1분, 5분, 마지막 순간에 플레이어가 느끼는 것 |
| 조작 | 무엇으로 조작하나 (키보드, 터치, 패드). 한 손으로 되나 |
| 선택 | 플레이어가 고르는 순간이 있나. 그 선택이 의미 있나 (정답이 하나면 선택이 아니다) |
| 수치 | 무엇을 조정 가능한 값으로 둘 것인가. 처음 값은 얼마인가 |
| 극단 상황 | 적이 아주 많을 때, 값이 0 이거나 최대일 때, 아무것도 안 할 때 |
| 겹침 | 같은 효과가 여러 개면 더하나, 곱하나, 하나만 적용하나 |
| 타이밍 | 레벨업 선택 중, 사망 순간, 일시정지 중에 이 기능은 어떻게 되나 |
| 성능 | 화면에 동시에 몇 개까지 생길 수 있나 |
| 범위 | 이번에 만들 것, 나중에 만들 것, 안 만들 것 |
| 필요 자원 | 그림, 소리, 이펙트가 얼마나 필요한가. 무료 에셋으로 되나 |
| 독창성 | 기존 게임의 이름, 캐릭터, 아트를 베끼지 않는다. 장르 문법만 쓴다 |

## 4. 기획서 작성

합의가 끝나면:

1. `AIDocument/_TEMPLATE_PLAN.md` 를 복사해 `AIDocument/기획/YYYY-MM-DD_<주제>.md` 로 쓴다
2. 사용자가 정한 것과 AI 가 정한 것 ("AI 판단") 을 구분해 적는다
3. `AIDocument/README.md` 문서 목록에 행을 추가한다.
   토론 중 내린 결정은 `AIDocument/결정_기록.md` 에, 다음 할 일은 `AIDocument/진행_현황.md` 에 반영한다
4. 새 대화 맥락이 없는 개발자 역할 서브에이전트에게 기획서만 주고
   "이 문서만 보고 만들 수 있나, 막히는 질문은 무엇인가" 를 확인받는다
5. 서브에이전트 질문을 세 가지로 나눈다
   - 이미 답이 있음: 기획서에 반영
   - 사소함: AI 가 정하고 "AI 판단" 으로 표시
   - 사용자만 답할 수 있고 결과물이 달라짐: 한 메시지에 모아 중요한 순서로 묻는다
6. 사용자에게 기획서 경로와 "AI 판단" 목록을 보여주고 승인을 받는다

## 5. 금지

- 코드, 씬, 프리팹, 에셋 생성
- 패키지 설치
- 커밋 (사용자가 그 턴에 직접 시켰을 때만. CLAUDE.md 커밋 규칙 참고)
- 사용자가 정하지 않은 것을 사용자가 정한 것처럼 적기

## 6. 끝

기획서가 승인되면 멈추고 보고한다. 개발은 사용자가 따로 시킬 때 시작한다.
