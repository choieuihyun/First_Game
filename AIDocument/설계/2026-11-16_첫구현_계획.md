# 뼈대 + 전장 반응 첫 기능 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 아키텍처 문서의 층 구조와 검증 루프를 세우고, 그 위에 "전장 반응" 최소 버전 (물질 4개, 방식 3개, 반응 3행, 마법 세트 3개) 을 올려 Unity 에서 플레이할 수 있게 한다.

**Architecture:** 판 상태와 규칙은 UnityEngine 을 모르는 순수 C# (`Game.Data`, `Game.Core`) 에 두고 30틱 고정 간격, 시드 랜덤 하나로 돌린다. 수치는 CSV. Unity (`Game.View`, `Game.App`) 는 상태를 읽어 그리고 입력을 명령으로 넘기기만 한다. 규칙 테스트는 Unity 밖에서 `dotnet test` 로 돈다.

**Tech Stack:** Unity 6000.3.28f1 (URP 2D, Input System), C# 9 / .NET Standard 2.1, NUnit 3, .NET SDK (Homebrew), bash.

**Spec:** `AIDocument/설계/아키텍처.md` (승인됨). 기획 배경은 `AIDocument/기획/2026-11-16_게임_컨셉.md`, 결정은 `AIDocument/결정_기록.md`.

## Global Constraints

- 모든 답과 주석은 한글. 주석과 로그에 특수문자를 넣지 않는다. 클래스, public 메서드, 주요 상수에 한글 주석 (`CLAUDE.md` 주석 규칙)
- **커밋하지 않는다.** 이 계획에는 커밋 단계가 없다. 각 Task 끝에서 결과를 보고하고, 사용자가 그 턴에 시킬 때만 커밋한다. push 금지
- `Game.Data`, `Game.Core` 는 `UnityEngine` 을 참조하지 않는다. asmdef 에 `"noEngineReferences": true`. 벡터는 `System.Numerics.Vector2`
- C# 9 까지만 쓴다. `record`, `init`, 파일 범위 네임스페이스, `Assert.Multiple` 을 쓰지 않는다. NUnit 은 3.x 공통 API (`Assert.That`, `Assert.AreEqual`, `Assert.Throws`) 만
- Core 안의 랜덤은 `Game.Core.Rng` 하나만. `System.Random`, `UnityEngine.Random`, `DateTime`, `Dictionary` 순회 순서에 결과가 의존하면 안 된다. 목록은 생성 순서 (Id 오름차순) 로 순회한다
- 기획 수치는 코드에 쓰지 않는다. 전부 `Assets/Resources/Data/*.csv` 에서 읽는다
- 전투 판정에 Physics2D 를 쓰지 않는다. 전역 이벤트 버스, DI 프레임워크, ScriptableObject 수치, 프리팹을 쓰지 않는다
- 패키지 추가 (`Packages/manifest.json`) 금지. 저장 직렬화는 `System.IO.BinaryWriter` 로 직접 쓴다
- 새 파일과 폴더의 `.meta` 는 직접 쓰지 않는다. Unity 배치 실행 (Task 9 의 `verify.sh unity`) 이 만든다. 파일을 지우거나 옮길 때는 `.meta` 도 함께
- `Library/`, `Temp/`, `Logs/`, `UserSettings/` 를 읽거나 고치지 않는다 (`Temp/UnityLockfile` 존재 확인만 예외)
- 화면이 없는 Unity 실행에서 `WaitForEndOfFrame` 을 쓰지 않는다. PlayMode 테스트에는 `[Timeout(180000)]`
- 검증 실패 시 고치고 다시 돈다. 같은 에러 3회 또는 시도 5회 초과면 멈추고 사용자에게 보고

### 스펙에서 달라지거나 구체화한 점 (AI 판단, 사용자 검토 대상)

- 스펙 12절의 "반응 4개" 중 감전과 수소 구름 생성은 같은 접촉 (물 + 번개) 이다. "한 접촉에 반응 하나" 규칙에 맞춰 `reactions.csv` 한 행 (전기분해) 에 효과 조각 두 개로 넣는다. 그래서 행은 3개다
- 효과 조각 6개 중 "상태 부여" 는 이번에 만들지 않는다. 쓰는 반응이 없다. 필요한 반응이 생길 때 추가한다
- `catalysts.csv`, `upgrades.csv` 는 만들지 않는다 (첫 기능 범위 밖)
- 폭발은 플레이어에게 피해를 주지 않는다
- HUD 와 룬 고르기 화면은 임시로 IMGUI (`OnGUI`) 로 만든다. 정식 UI 는 다음 기능
- 안드로이드 기기 빌드는 이 계획에 없다. 에디터 Play 까지

## Review Focus

스펙이 암시하지만 놓치기 쉬운 것. 각 줄의 테스트는 표시한 Task 에 들어 있다.

1. **엑셀이나 구글 시트에서 다시 저장한 CSV** (BOM, CRLF, 따옴표 안 쉼표, 끝의 빈 줄) 도 그대로 읽혀야 한다 → Task 2
2. **CSV 에 틀린 값** (없는 id 참조, 숫자 칸에 글자, 빈 칸) 이 있으면 파일, 행, 열을 짚은 메시지가 나와야 하고, 게임은 죽지 않고 그 메시지를 화면에 보여야 한다 → Task 3 (메시지), Task 9 (화면)
3. **한 틱에 룬 두 개를 줍거나, 고르는 중에 또 주운 경우** 룬이 사라지거나 멈춤이 풀리지 않으면 안 된다 → Task 7
4. **겹친 가스 구름 수십 개가 한꺼번에 터지는 경우** 한 틱 상한을 지키고 다음 틱으로 넘기며, 무한 연쇄나 멈춤이 없어야 한다 → Task 6
5. **전화가 오거나 앱이 백그라운드로 갔다 돌아온 경우** 멈췄다가 이어지고, 돌아온 순간 밀린 시간만큼 수백 틱이 한꺼번에 돌면 안 된다 → Task 9
