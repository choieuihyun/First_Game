## 1. 목적

이 게임은 물질, 반응, 적, 강화가 계속 늘어나고 바뀐다. 코드는 AI 가 쓰고 고친다.
그래서 아키텍처의 목표는 하나다: **AI 가 적은 맥락으로 안전하게 추가하고 고칠 수 있게.**

구체적으로:
- 새 물질이나 반응 추가는 **CSV 한 줄**로 끝난다. 코드는 완전히 새로운 효과 조각이 필요할 때만 건드린다
- 규칙이 잘못되면 **화면 없이 몇 초 안에** 테스트로 잡힌다
- 구조를 무너뜨리는 실수는 **컴파일 단계에서** 막힌다

## 2. 기획 결정과의 연결

| 아키텍처 선택 | 근거 결정 |
|---|---|
| 판 상태를 순수 C# 에 모은다 | D12 이어하기 필수 → 판 전체를 저장, 복원할 수 있어야 한다 |
| 고정 시간 간격 + 시드 랜덤 하나 | D8 랜덤은 상황에만, 규칙은 항상 같게 → 같은 시드면 같은 판 |
| 반응은 효과 조각을 조합한 데이터 | D7, D8 반응이 계속 늘어난다 |
| 반응 우선순위, 연쇄 한도, 프레임당 상한 | D8 결과물도 물질이라 무한 연쇄 가능, D12 이펙트 수 상한 |
| 수치는 CSV | D15 |
| 물질마다 색과 모양 필수 (테스트로 강제) | D12 색약 고려 |
| 모바일 성능 우선 | D10, D12 발열과 배터리 |
| 대상당 물질 하나 | D16 |

## 3. 층 구조

```
App   (시작, 화면 흐름, 저장 시점, 이어하기)
 │
View  (Unity: 그리기, 입력, 이펙트, 소리, UI)      ← UnityEngine 사용
 │ 읽기 + 명령 전달
Core  (순수 C#: 판 상태, 규칙, 시뮬레이션)          ← UnityEngine 사용 금지
 │
Data  (순수 C#: CSV 읽기, 검증 → Core 정의 객체)    ← UnityEngine 사용 금지
```

규칙:
- **Core 와 Data 는 UnityEngine 을 참조하지 않는다.** 어셈블리 정의 (asmdef) 에서 엔진 참조를 꺼서 물리적으로 막는다.
  벡터는 `System.Numerics.Vector2` 등 순수 C# 타입을 쓴다
- **View 는 Core 를 읽기만 한다.** Core 상태를 바꾸려면 명령 (이동 방향, 룬 선택 등) 을 넘긴다
- **Core 는 View 를 모른다.** Core 는 틱마다 "이번 틱에 일어난 일" 목록 (반응 발생, 적 사망, 룬 획득 등) 을 쌓고,
  View 가 그 목록을 읽어 이펙트와 소리를 낸다. 전역 이벤트 버스는 쓰지 않는다 (흐름 추적이 어려워진다)

### 어셈블리 (asmdef)

| 이름 | 참조 | 엔진 참조 |
|---|---|---|
| `Game.Data` | 없음 | 끔 |
| `Game.Core` | `Game.Data` | 끔 |
| `Game.View` | `Game.Core`, `Game.Data` | 켬 |
| `Game.App` | 위 전부 | 켬 |
| `Game.Tests.EditMode` | `Game.Core`, `Game.Data` | 테스트 전용 |
| `Game.Tests.PlayMode` | 위 전부 | 테스트 전용 |

## 4. 시뮬레이션

- **고정 틱:** Core 는 1초에 30번 (값은 `balance.csv`) 일정 간격으로 진행한다. 화면 프레임과 분리한다.
  View 는 틱 사이를 보간해 부드럽게 그린다
- **랜덤:** Core 안의 시드 랜덤 생성기 하나만 쓴다. `UnityEngine.Random` 과 `System.Random` 직접 사용 금지.
  생성기 상태도 저장 대상이다
- **입력:** View 가 모은 입력을 틱 단위 명령으로 Core 에 넘긴다. 같은 시드와 같은 명령열이면 같은 결과가 나와야 한다
- **충돌:** Unity 물리 (Physics2D) 를 전투 판정에 쓰지 않는다. Core 안의 간단한 공간 격자로 판정한다

## 5. 물질과 반응

### 물질이 존재하는 곳
- 적에게 묻은 물질 (젖음, 기름 등)
- 전장의 영역 (구름, 장판, 웅덩이)
- 날아가는 마법이 지닌 물질

### 물질 규칙 (D16, 사용자 확정)
- **대상 하나에 물질 하나.** 적 하나, 영역 하나는 물질을 하나만 가진다
- **반응하면 두 물질 모두 사라진다.** 결과물 (예: 수소 구름) 은 새 물질로 생긴다
- **반응하지 않는 물질이 오면 덮어쓴다**
- **시간이 지나면 사라진다.** 물질마다 지속 시간이 있다 (`substances.csv`)
- **계속 닿아 있으면 일정 간격으로 한 번씩 반응한다** (광선, 겹친 영역). 간격은 `balance.csv` (처음 값 0.5초, AI 판단)

### 반응이 일어나는 때
물질 A 와 물질 B 가 같은 곳에서 만날 때 (마법이 적이나 영역에 닿음, 영역끼리 겹침).
어떤 쌍이 무슨 반응을 일으키는지는 `reactions.csv` 가 정한다.

### 반응 해석 규칙
- **우선순위:** 한 접촉에서 반응은 하나만 일어난다. 여러 개가 해당하면 `priority` 가 높은 것
- **연쇄 한도:** 반응 결과물은 연쇄 깊이를 물려받는다. 깊이가 한도 (`balance.csv`, 처음 값 4) 를 넘으면 더 반응하지 않는다
- **틱당 상한:** 한 틱에 처리하는 반응 수, 전장 영역 수, 적 수에 상한을 둔다 (`balance.csv`). 넘친 반응은 다음 틱으로 미루거나 버린다
- **결정성:** 같은 틱 안의 처리 순서는 고정된 규칙 (생성 순서 등) 을 따른다. 리스트 순회 순서가 결과를 바꾸면 안 된다

### 효과 조각
반응과 마법의 결과는 아래 조각을 조합해 만든다. 새 반응은 조각 조합 (CSV) 으로 만들고,
조각 자체가 새로 필요할 때만 코드를 추가한다.

| 조각 | 하는 일 |
|---|---|
| 피해 | 대상에게 피해 |
| 상태 부여 | 둔화, 지속 피해 등 |
| 물질 부여 | 대상에게 물질을 묻힌다 |
| 영역 생성 | 구름, 장판 등을 만든다 (물질을 가진다) |
| 범위 폭발 | 반경 안 전체에 다른 조각을 적용 |
| 연쇄 | 근처 대상으로 옮겨 간다 |

조각 목록은 첫 구현에서 위 6개로 시작하고 필요할 때 늘린다.

### 촉매 (AI 판단, 첫 기능에는 없음)
- 촉매는 마법에 속한다. **반응을 일으킨 쪽 (닿은 마법) 의 촉매**가 그 반응에 적용된다.
  적이나 지형이 원래 지닌 물질과 반응할 때도 닿은 마법의 촉매가 적용된다
- 반응 결과물은 출처 마법과 촉매 효과를 물려받는다
- 기획서의 "연쇄 한 번 더" 는 효과 조각 "연쇄" 의 대상 수 +1 (옆 대상으로 한 번 더 옮겨 감) 이라는 뜻이다.
  반응 깊이 한도와는 다르며, 깊이 한도는 촉매로도 넘을 수 없다

## 5-1. 맵과 스테이지 (D16, 사용자 확정)

- **스테이지는 판을 시작할 때 고르는 맵이다** (예: 늪지, 광산). 맵마다 나오는 룬, 적이 지닌 물질, 지형이 다르다
- 한 판 안에서는 시간이 갈수록 웨이브가 세질 뿐 맵은 바뀌지 않는다
- **맵은 경계가 있는 넓은 전장이다.** 크기는 화면 여러 개. 지형 (웅덩이, 가스 지대 등) 은 판 시작 때 시드로 배치한다
- 공간 격자는 맵 크기에 맞춘 고정 격자로 충분하다
- 시제품 1 의 "웨이브마다 적 원소 저항이 바뀜" 은 넣지 않는다. 적이 지닌 물질이 같은 역할을 한다 (AI 판단)

## 6. 데이터 (CSV)

- 위치: `Assets/Resources/Data/*.csv` (Unity 에서 TextAsset 으로 읽힌다. 안드로이드에서도 별도 처리 없이 읽힌다)
- 인코딩 UTF-8. 첫 줄은 열 이름. 구글 시트에서 열고 CSV 로 내보내면 그대로 쓸 수 있게 한다
- 모든 행에 영문 `id` (코드와 다른 표에서 참조) 와 한글 `name` (화면 표시) 을 둔다
- Data 층은 문자열을 받아 파싱한다 (파일 접근은 App 이 한다). 그래야 테스트에서 파일 없이 검사할 수 있다
- **원본은 저장소의 CSV 파일이다 (AI 판단).** 사용자는 CSV 를 엑셀, Numbers, 구글 시트로 열어 고치고 CSV 로 다시 저장하거나,
  AI 에게 바꿀 값을 말한다. 구글 시트를 원본으로 두는 동기화 도구는 만들지 않는다 (필요해지면 그때 결정)

처음 표 (이름과 열은 첫 구현에서 확정):

| 파일 | 내용 |
|---|---|
| `substances.csv` | 물질: id, 이름, 색, 모양 |
| `deliveries.csv` | 방식: 탄환, 고리, 광선, 장판, 구름 |
| `catalysts.csv` | 촉매 |
| `reactions.csv` | 물질 A, 물질 B, 우선순위, 결과 |
| `effects.csv` | 반응과 마법이 쓰는 효과 조각 묶음 |
| `enemies.csv` | 적: 체력, 속도, 지닌 물질 |
| `stages.csv` | 스테이지 (맵): 크기, 나오는 룬 목록, 적 구성, 지형 물질 |
| `upgrades.csv` | 영구 강화와 해금 |
| `balance.csv` | 전역 값: 틱 속도, 연쇄 한도, 상한, 난이도 곡선 |

### 데이터 검사 (테스트로 강제)
- id 중복 없음
- 다른 표를 가리키는 값은 실제로 있는 id
- 모든 물질에 색과 모양이 둘 다 있음
- 같은 물질 쌍에 같은 우선순위 반응이 둘 이상 없음
- 숫자 열에 숫자가 아닌 값 없음

## 7. 저장과 이어하기

- 판 상태 (Core 전체 + 랜덤 생성기 상태 + 틱 번호) 를 저장한다
- 저장 시점: 앱이 백그라운드로 갈 때, 그리고 일정 간격 (`balance.csv`)
- 앱을 다시 열면 저장된 판이 있으면 이어하기를 묻는다
- 저장 파일에 버전을 넣는다. 데이터나 코드 버전이 달라 복원할 수 없으면 버리고 알린다
- 판 사이 성장 (영구 강화, 해금) 은 판 저장과 별도 파일
- 저장 형식은 구현 시 정한다. 단 새 패키지 (예: Newtonsoft JSON) 추가는 사용자 허락이 필요하다 (CLAUDE.md)

## 8. 성능 (모바일)

- 적, 탄, 이펙트 오브젝트는 재사용한다 (풀링)
- 근접 판정은 공간 격자 (모든 쌍 비교 금지)
- 상한은 `balance.csv` 에서 조정

## 9. 쓰지 않는 것 (AI 판단)

| 쓰지 않음 | 이유 |
|---|---|
| DOTS / ECS | 강력하지만 코드가 장황하고 흐름 추적이 어려워 AI 유지보수에 불리 |
| 의존성 주입 프레임워크 | 이 규모에 과함. 생성자로 직접 넘긴다 |
| 전역 이벤트 버스 | 누가 무엇을 듣는지 추적이 어렵다 |
| ScriptableObject 수치 데이터 | D15 |
| 프리팹과 씬에 로직 배치 | YAML 을 AI 가 안전하게 고치기 어렵다. 씬은 시작점만 두고 코드가 조립한다 |
| Physics2D 전투 판정 | 결정성과 저장 복원이 어렵다 |

그림, 이펙트, 소리는 문자열 키로 참조한다 (CSV 의 값이 키). 키와 실제 에셋의 연결은 View 가 맡는다.

## 10. 폴더 구조

```
Assets/
  Game/
    Data/        Game.Data asmdef. CSV 파싱, 정의 객체, 검사
    Core/        Game.Core asmdef. 판 상태, 시뮬레이션, 반응 해석, 랜덤, 저장 직렬화
    View/        Game.View asmdef. 그리기, 입력, 이펙트, UI
    App/         Game.App asmdef. 시작, 화면 흐름, 파일 저장
  Resources/Data/   CSV
  Tests/
    EditMode/    Core, Data 테스트 (빠름, 화면 없음)
    PlayMode/    짧은 실행 확인 (느림, 필요할 때만)
  Prototype/     시제품 1. 본 구조의 첫 기능이 돌면 삭제
```

시스템 하나가 커지면 `Core/<시스템>/` 으로 나누고 `AIDocument/시스템/<시스템>/SYSTEM.md` 를 만든다.

## 11. 검증 루프

UCWORKS 의 결정성 원칙을 가져온다: AI 가 쓴 코드는 정해진 검사를 통과해야만 완료다.

| 단계 | 언제 | 무엇 |
|---|---|---|
| 1. 규칙 테스트 (.NET) | Core, Data, CSV 변경마다 | Unity 밖에서 `dotnet test` 로 데이터 검사, 규칙 테스트, 시드 고정 시뮬레이션 (예: 시드 X 로 60초, 에러 없음, 반응 N 회 이상), 저장 후 복원해도 같은 결과. 몇 초 안에 끝나고 에디터가 열려 있어도 돈다 |
| 2. Unity 컴파일 | View, App 변경 시, 그리고 기능 완료 시 | Unity 배치 모드로 열어 컴파일 에러 확인 |
| 3. PlayMode 확인 | View 나 App 변경 시 | 씬을 짧게 돌려 실행 중 에러 없음 |
| 4. 사람 확인 | 기능 완료 시 | 사용자가 Play 로 손맛 확인 |

.NET 테스트 구성 (D17):
- 저장소 안 Unity 밖 폴더 (예: `Tools/CoreTests/`) 에 테스트 프로젝트를 두고, `Assets/Game/Core`, `Assets/Game/Data` 의 소스와
  `Assets/Tests/EditMode` 의 테스트 소스를 그대로 포함해 컴파일한다. 테스트 코드는 한 벌이고 Unity Test Runner 와 dotnet 양쪽에서 돈다
- Unity 와 같은 언어 수준을 지킨다: C# 9, .NET Standard 2.1 에 있는 API 만. 프로젝트 파일에 언어 버전을 고정한다
- .NET SDK 는 Homebrew 로 설치한다 (사용자 허락 받음, D17)

운영 규칙:
- Unity 경로는 `ProjectSettings/ProjectVersion.txt` 의 버전으로 정한다 (설치된 버전이 둘이다)
- 명령과 옵션은 항상 같은 것을 쓴다 (옵션이 바뀌면 전체 재임포트로 수 분 걸린 적이 있다). 정확한 명령은 스크립트 하나로 고정한다
- 로그와 결과 파일은 스크래치 폴더에 쓴다
- **에디터가 프로젝트를 열고 있으면 배치 모드가 실패한다.** 이때는 사용자에게 에디터를 닫을지 묻거나, 에디터의 Test Runner 창에서 돌리도록 안내한다
- 테스트 asmdef 는 검증된 형식을 쓴다: `overrideReferences: true`, `precompiledReferences: ["nunit.framework.dll"]`, `defineConstraints: ["UNITY_INCLUDE_TESTS"]`
- PlayMode 실행이 중단되면 `Assets/InitTestScene*.unity` 가 남는다. 확인 후 지운다
- 화면이 없는 모드에서 `WaitForEndOfFrame` 은 오지 않는다. 테스트에서 쓰지 않는다
- 실패 시 고치고 다시 돈다. 같은 에러 3회 또는 5회 시도 초과면 멈추고 사용자에게 보고한다

함께 만들 것 (첫 구현 계획에 포함). UCWORKS6.0-migration (`~/StudioProjects/UCWORKS6.0-migration`) 의 것은 Android 용이라
그대로 쓰지 않고, 위 운영 규칙에 맞춰 Unity 용으로 새로 만든다:
- 검증 스크립트 (위 1~3 을 한 번에)
- `/dev` 명령어 (승인된 기획서 기반 개발 + 검증 루프)
- CHANGELOG 자동 기록 훅 (`.cs`, `.csv` 감시)

## 12. 첫 기능 (AI 판단)

뼈대 위에 처음 올리는 기능은 **전장 반응 확인용 최소 버전** (시제품 2 의 역할). 아키텍처 검증과 재미 확인을 한 번에 한다.

| 넣는 것 | 빼는 것 (다음 기능으로) |
|---|---|
| 맵 1개 (경계 있음, 물웅덩이 지형 조금) | 맵 선택 화면, 맵 여러 개 |
| 물질 4개: 불, 물, 독가스, 번개 | 기름, 나트륨 등 나머지 물질 |
| 방식 3개: 탄환, 구름, 장판 | 고리, 광선 |
| 반응 4개: 독가스 + 불 = 가스 폭발, 물 + 번개 = 감전 (주변으로 퍼짐), 물 + 번개 = 수소 구름 생성 (감전과 함께), 수소 + 불 = 대폭발 (연쇄 깊이 확인용) | 촉매 |
| 젖은 적 1종 (적이 지닌 물질 확인용) + 일반 적 1종 | 영구 강화, 해금, 재화 |
| 룬 드롭, 주우면 멈추고 끼울 세트 고르기 | 사운드, 꾸민 그림 (도형으로 충분) |
| 마법 세트 3개 (첫 기능에서는 처음부터 3개 열림) | 저장과 이어하기 화면 |
| 시드 고정 시뮬레이션 테스트, 저장 후 복원 동일성 테스트 (Core 수준) | |

반응 수치와 정확한 결과는 첫 구현의 CSV 에서 정하고 플레이로 조정한다.

완료 기준: 검증 루프 1~3 통과, 그리고 사용자가 Play 로 반응을 직접 터뜨려 본 뒤 `Assets/Prototype/` 을 지운다.
